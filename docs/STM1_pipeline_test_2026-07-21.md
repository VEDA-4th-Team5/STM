# STM1 파이프라인 검증 (2026-07-21)

홀센서/불꽃센서 실물이 아직 배송 지연으로 도착하지 않은 상태에서, STM1(NUCLEO-F401RE) 보드만으로
FreeRTOS 태스크 로직 + UART 센서 프로토콜 파이프라인이 실제 보드에서 정상 동작하는지 검증한 기록.

## 테스트 환경

- 보드: NUCLEO-F401RE (STM1), 센서 미장착
- 클럭: 이번에 HSI → HSE(bypass, ST-Link MCO 8MHz)로 전환, PLLM=8/PLLN=336/PLLP=÷4로 SYSCLK 84MHz 유지
- 확인 도구: PuTTY, USART2(ST-Link VCP), 115200 8N1
- 코드: `TaskHallSensor`/`TaskFlameSensor`/`TaskPacketTX` 최초 구현 직후 상태

## 방법 및 결과

### 1. 불꽃센서 (PC0, 완전 플로팅)
- 아무것도 안 만졌을 때: `FLAME:flame_01:CLEAR:<seq>:<energy>` 가 1초마다 출력, energy는 2~3대(플로팅 픽업 노이즈 수준)로 안정적
- PC0 핀에 손가락을 대면: energy가 8~80대로 튀면서 placeholder 임계값(5.0)을 넘어 `ALERT`로 전환, 손 떼면 다시 `CLEAR`로 복귀
- → ADC→FFT→에너지합산(bin 1~20)→임계값 판정→UART 전송까지 파이프라인 전체가 실제 보드에서 정상 동작함을 확인. (에너지 임계값 5.0은 코드상 placeholder이며, 실제 화재 판정 임계값은 설계상 STM32가 아니라 Raspberry Pi 쪽에서 튜닝하도록 되어 있음 — 여기서 검증한 건 배관이지 판정 정확도가 아님)

### 2. 홀센서 (PA4 = MUX_COM, CD4051 멀티플렉서 없이 테스트)
- PA4에 직접 손가락/점퍼로 전압 변화를 주면 `SENSOR:sensor_01~04:OCCUPIED/VACANT:<seq>` 라인이 정상 출력됨
- 디바운스(250ms 안정) 후 상태 변화 시에만 이벤트 발행, sequence는 4개 슬롯 공용 카운터로 계속 증가 — 설계대로 동작
- 주의: 이 테스트는 CD4051 없이 **공통선(PA4)을 직접** 건드린 것이라, TaskHallSensor의 50ms 폴링 루프가 채널 0→1→2→3을 순회하는 동안 매 순간 "그때 선택된 채널"에 노이즈가 실려 4개 채널이 한 번에 다같이 반응한 것. 실제 CD4051+홀센서가 붙으면 각 채널이 독립적으로 반응해야 하며, 그건 센서 도착 후 채널별로 다시 확인 필요.

### 3. 두 태스크 동시 동작
테스트 중 홀센서 이벤트와 불꽃센서 이벤트가 UART 로그에 서로 인터리빙되어 출력됨 — 두 태스크가 하나의 `sensorEventQueueHandle` 큐를 공유하면서도 서로 막지 않고 정상 동작.

### 4. 개행 문자 버그
최초 테스트 시 PuTTY 화면이 계단식으로 오른쪽으로 밀리는 현상 발견 → `sensor_protocol.c`에서 줄 끝을 `\n`만 쓰고 `\r`을 빠뜨린 게 원인. `\r\n`으로 수정 완료. (데이터 자체는 처음부터 정상이었고 터미널 표시만 깨졌던 것)

## 알려진 한계 / 다음에 재확인할 것

- 화재 판정 임계값(5.0)은 실제 불꽃센서(DFR0076) 도착 후 3종 광원(태양광/형광등/라이터) 실측으로 다시 산정 필요
- 홀센서는 CD4051 + 실제 홀센서 4개 장착 후 채널별 독립 동작 재확인 필요
- 이번 검증은 STM1→UART(PuTTY) 구간까지만 확인한 것이며, Raspberry Pi 파서(`SENSOR:...`/`FLAME:...` 수신)와의 실제 연동은 아직 미검증
